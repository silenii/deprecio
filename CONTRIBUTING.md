# Руководство по контрибьютингу

## Git Workflow

### Ветвление
- `main` — стабильная ветка проекта и релизов.
- `feature/*` — короткоживущая ветка одной задачи.
- `fix/*` — исправление ошибки.
- `docs/*` — изменения документации.

Ветки создаются от актуальной `main` и удаляются после принятия Pull Request. Временные ветки с привязкой к неделям не используются.

### Коммиты

Используйте conventional commits по формату. Описание после двоеточия пишите на русском языке:

```
<type>(<scope>): <description>
```

**Типы:**
- `feat` — новая фича
- `fix` — исправление бага
- `refactor` — рефакторинг кода
- `test` — добавление тестов
- `docs` — документация
- `chore` — рутина, зависимости
- `perf` — улучшение производительности

## Публикация в GitHub и GitVerse

```bash
git push origin main
git push origin feature/название-задачи

# При настроенном зеркале origin отправляет изменения в GitHub и GitVerse.
# Если используются отдельные remote, отправьте ветку в каждый из них.
```

## Правила к коду
- Python 3.11+
- Type hints для всех функций
- Docstrings для основных классов
- Покрытие тестами >= 70%
- Соблюдение PEP 8

## Рабочий цикл

1. Создать ветку от `main` с понятным названием.
2. Делать небольшие логические коммиты на русском языке.
3. Обновить документацию, если изменилось поведение проекта.
4. Отправить ветку в GitHub и GitVerse.
5. Создать Pull Request в `main`, дождаться проверок и слить изменения.
