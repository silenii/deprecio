# Источники цен на смартфоны с пробегом

**Проверено:** 28 ноября 2026 года  
**Задача:** найти масштабируемые источники цен для большинства моделей смартфонов в Deprecio, по возможности бесплатно.

## Короткий вывод

Среди проверенных источников не нашлось бесплатного публичного API, который одновременно покрывает большинство российских моделей смартфонов и отдает проверенные цены завершенных сделок. Бесплатно доступны отдельные сигналы разного качества: цены активных объявлений, предложения магазинов с уценкой/восстановлением, trade-in оценки и цены зарубежных сделок. Их нельзя сводить в одну статистику под названием «рыночная цена».

Для широкого каталога Deprecio следует постепенно объединять три независимых потока: разрешенные предложения магазинов и партнеров, добровольно сообщенные цены реальных покупок/продаж и отдельные внешние ориентиры. Там, где наблюдений нет, показывать оценку с низкой уверенностью, не выдавая ее за найденную цену.

## Что именно измеряет цена

| Тип данных | Что означает | Можно использовать как цену сделки? |
|---|---|---|
| Цена активного объявления | Сумма, которую просит продавец; объявление могло не завершиться продажей | Нет. Это верхний ориентир предложения |
| Цена магазина на восстановленный/уцененный товар | Цена предложения магазина на конкретное состояние и гарантию | Нет. Это розничное предложение с условиями магазина |
| Trade-in / выкуп | Сколько конкретная программа готова заплатить за устройство после своей оценки | Нет. Это цена выкупа, обычно ниже розничной перепродажи |
| Завершенная сделка | Цена, реально уплаченная покупателем | Да, с учетом комиссии, состояния, комплектации и места сделки |
| Расчетная оценка | Модельная оценка по возрасту, характеристикам и другим наблюдениям | Нет. Ее нужно явно показывать как прогноз |

Снимок каталога на дату проверки показывает десятки карточек в разделе смартфонов с уценкой против существенно более широкого каталога новых устройств. |

Не смешивать цену восстановленного телефона и сумму выкупа. Проверить разрешенные пути сайта: его `robots.txt` ограничивает ряд API/фильтровых путей. |

## Проверенные факты и ограничения

1. **Podlovi не дает единообразный сегмент частных б/у сделок.** В его методологии уценка объединяет товары с разными причинами — например, витринные экземпляры, возвраты, поврежденную упаковку и восстановленные устройства. Поэтому в Deprecio стоит оставлять только явный `UsedCondition` и подписывать источник как магазинное предложение. [Методология Podlovi](https://podlovi.ru/methodology/), [каталог смартфонов с уценкой](https://podlovi.ru/moscow/catalog/phones/ucenka/)

2. **Текущая интеграция Podlovi в проекте не обещает покрытие большинства моделей.** Она находит страницы по каталогу Deprecio и sitemap, берет только явные предложения `UsedCondition` и не более двух карточек товара на модель за цикл. Sitemap-совпадение означает, что товарная страница существует, но не гарантирует наличие б/у предложения. Это видно и на примере карточек, где все предложения новые. [Код сборщика](../../deprecio/harvester/podlovi.py), [пример карточки Podlovi](https://podlovi.ru/m/smartfon-samsung-galaxy-s23-ultra-12-512-gb-GALAXYS23ULTRA512GB/)

3. **M.Video представляет две разные сущности:** магазинную продажу восстановленных устройств и программу выкупа. Официальное сообщение M.Video-Eldorado описывает trade-in для широкого набора брендов; цена выкупа не является ценой перепродажи телефона. Автоматический сбор нужно сверять с действующими правилами доступа сайта. [Сообщение о программе trade-in](https://www.mvideoeldorado.ru/ru/press-centr/press-relizy/detail/3468), [каталог восстановленных устройств](https://www.mvideo.ru/smartfony-i-svyaz-10/smartfony-761/f/sostoyaniye=vosstanovlenny), [robots.txt M.Video](https://www.mvideo.ru/robots.txt)

4. **API маркетплейса может быть бесплатным и все равно не решать задачу.** Yandex Market Partner API и Ozon Seller API предназначены для интеграции продавца с его товарами, ценами и заказами. Это не открытый поток конкурентных цен. Ozon отдельно описывает Statistics API, содержащий рыночные данные, и предлагает независимым аналитическим сервисам запрашивать коммерческий доступ. [Yandex Market для партнеров](https://partner.market.yandex.ru/integrations), [Ozon Statistics API](https://dev.ozon.ru/news/256-Novyi-API-dlia-polucheniia-dannykh-Statistics-API/), [Ozon Seller API](https://dev.ozon.ru/start/40-Seller-API-API-prodavtsa-dlia-raboty-s-marketpleisom)

5. **У eBay нужно отделять активные и завершенные объявления.** Browse API ищет активные предложения. Marketplace Insights ближе к статистике завершенных продаж, но официальная документация говорит, что он ограничен и не открыт новым пользователям. [Фильтры Buy API](https://developer.ebay.com/api-docs/buy/static/ref-buy-browse-filters.html), [Buy Browse API](https://developer.ebay.com/api-docs/buy/api-browse.html)

6. **Swappa публикует разные показатели для разных задач.** На ценовых страницах разделены средние цены объявлений и состоявшихся продаж; это полезный зарубежный сигнал, но не российская оценка. Публичный массовый API в проверенных материалах не найден. [Swappa prices](https://swappa.com/prices), [описание методики Swappa](https://swappa.com/blog/iphone-pricing-data/)

7. **API классифайдов не следует считать доступным только потому, что сайт открывается.** В доступных официальных материалах Avito не подтвержден открытый бесплатный API для поиска всех объявлений; текущий проектный выбор уже исключает Avito из-за платного доступа. Для Юлы также не найден документированный публичный API рыночного поиска. Отсутствие найденной документации не доказывает, что закрытых партнерских условий не существует. [Каталог API Avito](https://www.avito.ru/developers/api-catalog), [справочный центр Юлы](https://help.youla.ru/)

## Рекомендованный путь для Deprecio

### Сейчас

1. Оставить Podlovi как бесплатный сборщик магазинных восстановленных/подержанных предложений. В карточке отдельно показывать тип источника, продавца, состояние, память, дату наблюдения и ссылку. Не смешивать эти цены с ценой частной сделки.
2. Измерить покрытие по всему каталогу: для каждой модели фиксировать `есть страница`, `есть явная UsedCondition цена`, `нет предложения`, `ошибка/страница недоступна`. Считать процент моделей с актуальным предложением; одно лишь совпадение модели по sitemap не считать данными.
3. Добавить добровольную форму «Продал/купил смартфон за …» в Telegram и веб-клиент: модель и память, цена, состояние, город/регион, дата и признак состоявшейся сделки. Собирать только нужные поля и не требовать ФИО, телефон, IMEI или чек.

### Следующий канал роста

4. Подготовить простой партнерский CSV-шаблон и обратиться к магазинам восстановленной техники, независимым реселлерам, комиссионным сетям и сервисам выкупа. Минимальные поля: `partner_id`, название/модель, память, состояние/grade, цена, валюта, наличие, регион, URL, `updated_at`, тип цены (розничная/выкуп). Получать данные только с явного разрешения и согласовать частоту/срок хранения.
5. Запрашивать фид у крупных сетей (например, M.Video/MTS/Билайн) отдельным письмом. Если дают лишь оценку trade-in, хранить ее как `buyback_quote`, а не как `used_sale_price`.
6. Использовать Swappa/eBay только как отдельный зарубежный ориентир или набор для проверки тенденций, с исходной валютой и географией. Не конвертировать его напрямую в российскую медиану.

### Правила отображения

- Разделить типы цены на `private_asking`, `private_sold`, `dealer_refurbished`, `buyback_quote`, `estimated`.
- Рассчитывать медиану и диапазон внутри одного типа цены, совпадающей модели/памяти/сопоставимого состояния и разумного временного окна.
- Всегда показывать количество наблюдений и дату последнего обновления. При одном предложении показывать цену предложения, а не «медиану рынка».
- Для самоотчетов отделять подтвержденные сделки от неподтвержденных, дедуплицировать и отсекать явные ошибки/аномалии.
- Если данных недостаточно, выводить «мало данных» и, при необходимости, отдельную оценку с низкой уверенностью вместо смешения разных типов цен.

## Решение

Самый реалистичный бесплатный путь к охвату большинства моделей — не поиск одной волшебной API, а комбинация: **партнерские магазинные фиды + добровольные фактические сделки пользователей + Podlovi как дополнительный слой предложений**. В краткосрочной перспективе Podlovi повышает число наблюдаемых карточек, но его текущий поднабор UsedCondition не обеспечит большинство моделей. Полноценные российские цены завершенных сделок появятся только при договорном обмене данными или накоплении сообщества; расчетная модель может заполнить пробелы, но должна оставаться явно прогнозной.
